# Efficient Latent Diffusion Optimization

**Improving inference speed while preserving image quality** — CMPE 261 course project.

| Member | SJSU ID | Focus |
|---|---|---|
| Ruixiang Huang | 013483639 | Model implementation, optimization experiments, performance evaluation |
| Dan Lam | 011383814 | Dataset preparation, image-quality evaluation, visualization |
| Haoran Jiang | 018321927 | Literature review, experiment analysis, report preparation |

We take a pretrained Stable Diffusion v1.5 pipeline (no training) and measure how
**fewer denoising steps**, **alternative schedulers (DDIM, DPM-Solver++)**, **FP16 inference**
and **feature caching (DeepCache)** affect latency, peak GPU memory, throughput and image quality
(CLIP Score, FID, LPIPS-vs-baseline) — first one factor at a time, then combined.

## Setup

```bash
python -m venv .venv
source .venv/bin/activate
pip install --upgrade pip
```

Install PyTorch for your platform first (see <https://pytorch.org/get-started/locally/>), e.g. on a CUDA 12.1 node:

```bash
pip install torch torchvision --index-url https://download.pytorch.org/whl/cu121
```

Then the project and its dependencies:

```bash
pip install -e ".[dev]"
```

Local Macs can run everything end-to-end on `mps`/`cpu` for debugging with a handful of prompts,
but **all reported numbers must come from the same GPU type on HPC** (memory stats are CUDA-only).

The SD1.5 weights download automatically from Hugging Face on first use
(`stable-diffusion-v1-5/stable-diffusion-v1-5`). On HPC, set `HF_HOME` to scratch space.

## Workflow

### 1. Freeze the prompt set (once, Dan)

Download COCO 2017 annotations (`captions_val2017.json`) and, if computing FID, the val2017 images.

```bash
python scripts/prepare_prompts.py --coco-captions /path/to/captions_val2017.json --num-coco 500 --out data/prompts/eval_prompts.jsonl
```

This writes a fixed JSONL with `id`, `prompt`, `source`, `category`, `seed` (and `coco_image_id` for FID references).
Commit it — **every experiment uses this exact file and these exact seeds.**

### 2. Run experiments (Ruixiang)

```bash
python scripts/run_experiments.py configs/experiments/00_baseline.yaml
```

```bash
python scripts/run_experiments.py configs/experiments/01_steps.yaml --num-prompts 20
```

`--num-prompts` is for quick checks; omit it for real runs. Use `--only <run_name>` to rerun a single run.

On HPC: `sbatch scripts/hpc/run_gpu.slurm configs/experiments/01_steps.yaml`

### 3. Evaluate quality (Dan)

```bash
python scripts/evaluate_quality.py --runs "results/*" --baseline results/baseline --fid-ref /path/to/coco/val2017
```

CLIP Score is always computed; LPIPS-to-baseline when `--baseline` is given; FID when `--fid-ref` is given.

### 4. Summarize (Dan / Haoran)

```bash
python scripts/summarize.py --runs "results/*" --out report/figures
```

Produces `results/summary.csv`, latency-vs-CLIP and memory plots, and side-by-side image grids.

## Experiment matrix

| Steps | `01_steps.yaml` | 10 / 20 / 30 / 50 steps | PNDM, FP32 |

| Combined | `05_combined.yaml` | best settings stacked, plus leave-one-out ablations | — |

Add a new run by appending an entry to the relevant `runs:` list — only list the keys that differ from `base.yaml`.

## Reproducibility rules

1. Same prompts file, same per-prompt seeds, same resolution (512×512) and guidance scale (7.5) everywhere.
2. Report perf numbers only from GPU runs on one hardware type; record the GPU name (saved in `perf.json`).
3. Warm-up iterations are excluded from timing; CUDA is synchronized before every timer read.
4. Never edit `results/` by hand. Re-run instead.
5. Final tables/plots must be regenerable with `scripts/summarize.py`.

## Git conventions

- `main` stays runnable. Work on short branches: `feat/deepcache`, `eval/fid`, `report/draft-1`.
- Open a PR and get one teammate's review before merging.
- Don't commit images, checkpoints or `results/` (see `.gitignore`); share them via Google Drive / HPC paths.
